# i18n desk

## 特色

- **多語系並排編輯**：每個語系一欄、每個 key 一列，每一格都能直接改。上萬列也不卡（虛擬捲動）。
- **diff 最小**：寫回時照每個檔原本的 key 順序輸出，並保留換行字元、縮排與檔尾換行。改一句話就是一行 diff。
- **自動判斷資料夾版面**：扁平、每個語系一個資料夾、每個語系底下好幾份檔都認得，判斷錯了可以手動改。
- **多檔分頁**：一個語系底下有好幾份檔時，一份一個分頁。
- **變數一致性檢查**：比對同一個 key 在各語系裡的 `{{name}}` / `{0}`，跟多數不一樣的標紅。
- **備註檔**：給譯者看的說明存在 `_comments.json`，不會混進語系檔。
- **草稿自動保存**：編到一半關掉分頁，再打開會問要不要還原。
- **GitLab 一鍵提交**：從倉庫載入，改完把所有變更打包成一個 commit，順便開 Merge Request。

## 資料去哪裡

* 檔案只在瀏覽器裡處理，不會上傳到任何地方。
* GitLab 整合: 內容會從瀏覽器直接送到你填的那台 GitLab。


| 位置             | 名稱                              | 內容                                                               |
| ---------------- | --------------------------------- | ------------------------------------------------------------------ |
| `localStorage`   | `i18n-desk-layout`                | 版面偏好：顯示欄位、凍結、欄寬、列高、聚焦與對照語系、分區面板收合 |
| `localStorage`   | `i18n-desk-patterns`              | 手動改過的路徑樣板（依資料夾名稱或 GitLab 專案記）                 |
| `localStorage`   | `i18n-desk-gitlab`                | GitLab 位址、專案、分支、路徑。**不含 token**                      |
| `sessionStorage` | `i18n-desk-gitlab-token`          | GitLab token，分頁關掉就沒了                                       |
| `localStorage`   | `i18n-desk-gitlab-token`          | 只有勾了「在這台電腦記住 token」才會寫進來                         |
| IndexedDB        | 資料庫 `i18n-desk`，store `state` | 未匯出的草稿。只有改過的內容，**不含 token**                       |


## 瀏覽器支援

| 瀏覽器          | 本機資料夾                                 | 載入 JSON 檔 / 下載 | GitLab |
| --------------- | ------------------------------------------ | ------------------- | ------ |
| Chrome、Edge    | 可以直接寫回（選擇資料夾或拖放資料夾都行） | 可以                | 可以   |
| Firefox、Safari | 唯讀：讀得進來，改完要下載再自己放回去     | 可以                | 可以   |

- 寫回資料夾靠的是 File System Access API（`showDirectoryPicker`），目前只有 Chromium 系的瀏覽器有。
- 這個 API 需要 secure context：正式站要用 **HTTPS**。
- 建議版本：Chrome / Edge 111 以上、Firefox 128 以上、Safari 16.4 以上（Tailwind CSS v4 的最低需求）。

## 使用方式

### 來源與輸出

上面那排按鈕分成「來源」和「輸出」兩組，差別只在**能不能寫回原檔**。標題旁邊的徽章會一直顯示目前在哪個模式。

| 按鈕            | 分組 | 作用                                                                   |
| --------------- | ---- | ---------------------------------------------------------------------- |
| 選擇語系資料夾… | 來源 | 讀資料夾。Chrome / Edge 會同時拿到寫回的權限，其他瀏覽器是唯讀         |
| 載入 JSON 檔…   | 來源 | 讀單獨的 JSON 檔，沒有寫回的權限                                       |
| 從 GitLab 載入… | 來源 | 讀倉庫裡的語系資料夾，改完可以 commit 回去                             |
| 儲存到資料夾    | 輸出 | 覆寫原本的檔案。只有可寫的資料夾模式才有                               |
| 提交到 GitLab   | 輸出 | 送一個 commit 回去。只有 GitLab 模式才有                               |
| 下載變更        | 輸出 | 只匯出改過的檔。單一 JSON 直接下載，多個檔打包成 `locales-changed.zip` |
| 下載全部 (zip)  | 輸出 | 匯出所有語系檔，不管有沒有改（`locales.zip`）                          |

- **拖放**：把語系資料夾或 JSON 檔拖到頁面任何地方就會載入。在 Chrome / Edge 拖進來的資料夾一樣可以寫回，第一次儲存時瀏覽器會問你要不要給寫入權限。一次只能拖一個資料夾，或只拖 JSON 檔。
- **唯讀資料夾**：Firefox / Safari 選資料夾或拖資料夾時，讀得到每個檔的路徑，所以什麼版面都讀得進來。改完按「下載變更」，zip 裡的路徑跟原本的資料夾一樣，解壓縮蓋回去就好。
- **載入 JSON 檔**只拿得到檔名，不知道檔案原本在哪個資料夾。所以如果好幾個檔同名（例如每個語系都叫 `translation.json`），會擋下來並請你改用「選擇語系資料夾…」或「從 GitLab 載入…」。
- 兩個下載按鈕在任何模式都能用，想留備份或交給別人時很方便。
- 還有沒存的變更時，關閉分頁會先跳出提醒。

### 編輯、篩選、搜尋、分區

- **編輯**：點任何一格直接打字。改過的格子會標起來，`Esc` 把這一格還原成載入時的內容。工具列右邊顯示目前列數和改了幾格。
- **篩選**：全部、未翻譯、變數不一致、有備註、已修改。每個篩選旁邊的數字是符合的 key 數。
- **變數不一致**：同一個 key 的所有非空值互相比對變數組合（`{{name}}` 與 `{0}` 兩種寫法都認），以多數為準，跟多數不同的標紅。分不出多數時（例如只有兩個語系填了而且不一樣）整排都標起來。
- **搜尋**：key、任一個看得到的語系內容、備註都會搜。
- **分區**：左邊的分區樹照 key 裡的 `.` 分層（`history.labels.bet` → `history` / `labels`）。只有前後都是一般字元的 `.` 才算分隔，所以 `Loading...`、`Hello. World` 不會被拆開。點一區只看那一區，再點一次或點「全部」取消。旁邊的紅色數字是那一區有幾個 key 至少缺一個（看得到的）語系。面板可以收合。
- **篩選與統計只算看得到的欄位**：只顯示德文時，「未翻譯」就是德文沒填的數量。變數檢查的多數決仍然用所有語系判斷，只是只有看得到的欄位會標紅。

### 新增、改名、刪除

- **新增 key**：滑過一列時，下框線左側會出現 `+`，按下去會在那一列下面插入新的 key，並預先填好同一層的路徑。工具列的「新增 key」則插在目前選中的那一列（淺藍色底）下面。寫進檔案時也是緊接在那一列後面。新 key 在 KEY 欄會標「新」，**要填了內容才會寫進檔案**。
- **結構衝突**：新增或改名時會擋掉重複的 key、新 key 是現有 key 的上層、以及現有字串不能再往下分層（已經有 `common.copy` 就不能加 `common.copy.deeper`）。
- **改名**：滑過 KEY 欄出現的鉛筆圖示。所有語系的內容與備註都會跟著搬，位置不變。
- **刪除 key**：滑過 KEY 欄出現的 `×`。會先告訴你有幾個語系有內容，確認後才刪。
- **新增語系**：表格最右邊表頭的 `+`。輸入代碼（例如 `es`），會照目前的[版面](#支援的檔案版面)建立檔案。按下去只是先開一欄，**要儲存之後檔案才會出現**；還沒儲存的語系表頭上有 `×` 可以直接移除。
- **刪除語系**：滑過語系表頭，按右邊的 `×`。這時只是先標記，要等「儲存到資料夾」或「提交到 GitLab」才會真的刪檔。存檔之前可以到「顯示欄位」選單按「復原」。一個語系有好幾份檔時會一起刪，旁邊的 `.meta` 也一起刪；語系自己的資料夾空了就一起收掉，裡面還有別的檔案就留著。載入 JSON 檔的模式寫不回原處，所以沒有這個按鈕。
- 至少要留一個語系。

### 聚焦模式與對照語系

語系一多，表格就要一直左右捲。按語系列最左邊的「**聚焦**」，畫面只留 KEY、備註（沒隱藏的話）、**對照語系**和**一個目標語系**：

- **對照語系**擺在目標語系左邊，通常選翻譯的來源語言。沒選過的話依序挑繁中、簡中、中文、英文，都沒有就用第一個。可以從「對照」選單換。
- **換目標語系**：點語系列上的 chip，或按 `Alt + ←/→`（Mac 是 `Option`）依序切換，會跳過對照語系。焦點在輸入格裡也能用。
- 再按一次「聚焦」，或點目前的目標語系，就回到原本那組顯示欄位。聚焦期間不能改「顯示欄位」。

沒開聚焦時，語系列上的 chip 是快速定位用的：點一下捲到那一欄，隱藏中的欄位會先叫出來。chip 上的紅色數字是那個語系還缺幾個 key。

**對照語系只影響畫面。** 編輯器沒有「來源語系」的概念：每個語系都是平等的欄位，都能編輯，存檔也不會拿誰當基準。要 fallback 到哪個語系是你的程式（例如 i18next 的 `fallbackLng`）決定的。

### 顯示欄位、凍結、欄寬、列高

- **顯示欄位**選單裡每一欄有兩個開關：勾選框決定要不要顯示，「釘」決定要不要凍結在左邊。每個語系旁邊會標「已改 N」，隱藏中的語系也看得到自己還有沒存的修改。
- **凍結**：預設是 KEY + 備註。把某個語系釘起來就會一直留在左邊，往右捲去看別的語系時拿來對照。KEY 永遠顯示也永遠凍結。凍結區最多占畫面寬度的七成，超過會擋下來。
- **欄寬**：拖表頭的右邊界調整，範圍 80–720px。雙擊那條界線還原這一欄，選單底下的「全部還原」還原所有欄。
- **列高**：工具列的「列高」選 1 / 2 / 3 行。超過一行時內容會自動折行，KEY 也一起折。列高是整張表統一的，不是逐列長高，這樣上萬列的虛擬捲動才順。滑到格子上會有 tooltip 顯示完整內容。
- **隱藏只影響畫面**：被隱藏的語系有未儲存的變更，照樣會被存檔或下載。
- 深色模式跟著系統設定。
- 這些設定都記在瀏覽器裡，下次打開維持原樣。

### 草稿與還原

編輯中的內容會自動存在瀏覽器的 IndexedDB。關掉分頁再打開、載入同一份資料時，會問要不要還原。草稿會記下當初是從哪個來源改的，跟現在的來源不一樣時會在詢問時講明，避免把別的倉庫的修改還原到這一份上。存檔、commit 成功或捨棄之後草稿就會清掉。

### 鍵盤快捷鍵

| 按鍵                  | 動作                                                       |
| --------------------- | ---------------------------------------------------------- |
| `Enter`               | 移到下一列的同一欄                                         |
| `Shift + Enter`       | 移到上一列的同一欄                                         |
| `Ctrl + ↓` / `⌘ + ↓`  | 移到下一列的同一欄                                         |
| `Ctrl + ↑` / `⌘ + ↑`  | 移到上一列的同一欄                                         |
| `Esc`                 | 把這一格還原成載入時的內容（刪除 key 不能用這個還原）      |
| `Alt + ←` / `Alt + →` | 聚焦模式下切換到上一個 / 下一個目標語系（Mac 是 `Option`） |

- 輸入法選字中（例如注音、拼音還沒送出）按 `Enter` 或其他鍵都交給輸入法，不會移動格子。
- **格子裡不能輸入換行**：多行模式下 `Enter` 一樣是移到下一列。真的需要換行的字串，請在值裡用轉義字元或交給程式處理。

## 支援的檔案版面

### 路徑樣板

語系檔放在哪裡用一個**路徑樣板**描述，`{code}` 是語系代碼，`{ns}` 是同一個語系底下的哪一份檔：

```text
扁平                  每個語系一個資料夾       每個語系底下好幾份檔
locales/              locales/                 assets/i18n/
  en.json               en-US/translation.json   eng/json/text.json
  zh-TW.json            zh-TW/translation.json   eng/json/errorMessage.json
  de.json               de/translation.json      tch/json/text.json
  _comments.json        _comments.json           tch/json/errorMessage.json
                                                 _comments.text.json

{code}.json           {code}/translation.json  {code}/json/{ns}.json
```

按檔名分資料夾的 `{ns}/{code}.json`（`common/en.json`、`errors/en.json`）也認得。

### 自動判斷

- 載入時把每個路徑的每一段都試著當語系代碼，挑認得的語系代碼最多的切法。所以選到語系資料夾的上一層也沒關係，旁邊不相干的 JSON 不會被當成語系。
- 最多往下看五層（含檔名）。不會進去的資料夾：點開頭的（`.git` 等）、`node_modules`、`dist`、`build`、`library`、`temp`、`local`、`profiles`。資料夾太大時會請你直接選語系所在的那一層。
- **只讀對得上樣板的檔**，`locales/en-US/foo/bar.json` 這種對不上的一律不碰，以免生出一個不存在的語系再寫回去。
- 語系代碼照樣板那一段取：`en.json` → `en`、`en-US/translation.json` → `en-US`、`eng/json/text.json` → `eng`。
- 不標準的代碼也認得：`eng`、`sch`、`tch`、`jp`、`kr` 等會顯示成「英文 ENG」「簡中 SCH」「繁中 TCH」。認得的語系超過一半時照常見的順序排欄（英文、繁中、簡中…），否則照字母排。

### 手動修改樣板

判斷結果顯示在頂端資料夾名稱旁邊（例如 `{code}/json/{ns}.json`）。讀錯了點它就能改，改過的會依資料夾名稱，或 GitLab 的位址、專案與路徑記住，下次載入同一個來源直接用；清空再按確定就改回自動判斷。完全看不出版面時會直接問你。

### 一個語系底下好幾份檔

`text.json`、`errorMessage.json` 這種版面，表格上方會多一排分頁，一次編一份：

- 每一份的 key、備註、篩選、分區各自獨立；顯示欄位、凍結、欄寬、聚焦則是共用的。
- 分頁上的數字是那一份還有幾個檔沒存。儲存、提交、下載變更與草稿都會一次處理**所有分頁**。
- 某個語系少了其中一份也沒關係：那一份的分頁裡就沒有這個語系，在那個分頁按 `+` 新增同一個代碼，只會補上缺的那一份。
- 新增語系時每一份都會建，資料夾不存在就一起建。

### 平層與巢狀

- **巢狀**（`{"common": {"ok": "OK"}}`）在表格裡攤平成 `common.ok`，寫回時還原成巢狀。
- **平層**（`{"common.ok": "OK"}`）：所有語系檔都沒有巢狀，而且真的有 key 用 `.` 分組時，整份當成平層。分區樹照樣能用（標「虛擬」），新增、改名的 key 和備註檔都寫成平層，結構衝突只擋重複。
- 只含 `Loading...` 這種 key 的平層檔不算平層，新 key 照 `.` 寫成巢狀。

### key 本身含 `.`

巢狀檔案裡可能有本身就含 `.` 的 key（例如 `"Setting-AmbientSounds..."`）。載入時會記下它實際的分層，寫回時照原樣，不會被拆開。

- 新增或改名時打的 key 照 `.` 分層，所以這種 key 不會再變多。
- 同一個檔裡兩種寫法攤平後撞在一起（`{"a.b": …, "a": {"b": …}}`）會在載入時報錯，請先手動改掉其中一個。

### 備註檔

JSON 沒有註解，所以備註放在語系們的共同上層的 **`_comments.json`**，結構跟語系檔一樣：

```json
{
  "order": {
    "labels": {
      "name": "顯示在明細表頭，長度上限 12 字"
    }
  }
}
```

- 底線開頭的檔案不會被當成語系檔。如果你的程式用 glob 載入語系檔，記得排除 `_` 開頭的檔案。
- 一個語系底下有好幾份檔時一份一個：`_comments.text.json`、`_comments.errorMessage.json`。
- 跟語系檔用同樣的序列化規則，diff 一樣乾淨。

### 格式保留

- 每個檔照它**原本的 key 順序**輸出，新填的 key 才接在後面，沒有統一排序。沒有修改過的檔序列化結果跟原檔逐位元相同。
- 保留換行字元（CRLF / LF）、縮排（2 格、4 格或 tab）和檔尾有沒有換行。新增的語系檔與備註檔跟著現有檔案的多數走。
- 原本就在檔案裡的 key 被清空也不會刪掉；檔案原本沒有的 key，點進去沒填東西也不會平白多一個空值。

### Cocos Creator 的 `.meta`

刪除語系時，語系檔與語系資料夾旁邊的 `.meta` 會一起刪（資料夾模式與 GitLab 都是）。新增的語系不會產生 `.meta`，用 Creator 打開專案會自動補上，記得一起 commit。

## GitLab 整合

直接讀倉庫裡的語系資料夾，改完開一條分支、送一個 commit 回去，省掉「下載 → 放回去 → 自己 commit」。序列化與格式保留的規則跟本機資料夾完全一樣。資料夾模式和下載不受影響，沒有 GitLab 帳號也照常能用。

### 前置條件

- GitLab.com 或自架的 GitLab 都可以。
- **自架 GitLab 必須允許來自部署網域的跨來源請求（CORS）**。GitLab 的 `/api/v4` 預設就會回 CORS 標頭；如果前面有反向代理或防火牆，要讓它放行 `OPTIONS` preflight 與 `Access-Control-*` 標頭。被擋的話精靈會顯示「連不上…這台 GitLab 不接受跨來源請求」。
- **不支援裝在子路徑底下的 GitLab**（例如 `https://example.com/gitlab`）。位址欄只保留 scheme + 網域（+ port），貼專案網址或 SSH clone 網址也會自動整理成這樣。
- 授權只用 access token。**沒有 OAuth**，所以不需要在 GitLab 註冊 application，也不用設定 redirect URI。

### 申請 token

精靈第一步的「在 GitLab 申請一個 token」會把申請頁（`/-/user_settings/personal_access_tokens`）開好，名稱和權限會盡量預填：

1. 按 **Add new token**（有些版本直接就是一張表單）
2. 名稱隨意，到期日挑一個
3. **權限只勾 `api`**
4. 按 **Create personal access token**
5. 把畫面上的 `glpat-…` 複製回來貼進第一步

這串字只會出現一次，弄丟就再申請一個，舊的可以直接撤銷。如果頁面開不起來（有些 GitLab 站台的路徑不一樣），從右上角頭像 → **Edit profile** 或 **User settings** → **Access tokens** 也是同一頁。

**為什麼要 `api`**：這個工具透過 REST API 列專案與分支、讀檔、建立 commit、開 MR。`read_repository` / `read_api` 只能讀；`write_repository` 只能用 Git over HTTP 推送，不能呼叫 REST API 建立 commit。能寫入的 API 權限只有 `api`。


### 從 GitLab 載入引導流程

| 步驟          | 要做什麼                                                      |
| ------------- | ------------------------------------------------------------- |
| 1. 連線       | 填 GitLab 位址，貼上 token。按下一步會先用 `/user` 驗證 token |
| 2. 專案       | 列出你是成員的專案；打字搜尋時連不是成員但看得到的專案也會找  |
| 3. 分支       | 從分支清單點一個，預設分支排第一個                            |
| 4. 語系資料夾 | 從倉庫根目錄一層層點進去，每一層都會提示像不像語系資料夾      |

- 第四步的提示（例如「看起來是 `{code}/json/{ns}.json`：7 個語系 × 2 份檔」）只看了一頁檔案清單，真正的判斷在載入當下，規則跟[本機資料夾](#自動判斷)一樣。選到語系根目錄或它的上一層都可以。
- 只會下載對得上樣板的檔，一個檔一個請求，不會整個倉庫抓回來。
- 用過一次之後，第一步會多一顆「**直接載入上次的**：`group/repo@main · src/locales`」，省掉三次點選。手上還有沒送出去的變更時一樣會先問你。

### 提交

按「提交到 GitLab」會列出這次要寫的檔案，填好分支與 commit 訊息就送出：

- **一個原子 commit**：所有變更的檔案（含備註檔）透過 GitLab 的 Commits API 打包成同一個 commit，不會出現只寫了一半的狀態。
- 新增的檔用 `create`，原本就有的用 `update`；刪除語系時連同旁邊的 `.meta` 一起 `delete`。
- **衝突偵測**：載入時記下那條分支的 commit id，送出前再問一次。不一樣就擋下來並顯示新舊 id，請你重新載入，不會蓋掉別人推的東西。
- **預設開新分支**：分支欄預先填 `i18n/<今天日期>`（例如 `i18n/2026-01-31`），從你載入的分支開出去。
- **自動開 MR**：預設勾「順便開一個 Merge Request 回」原本的分支，MR 合併後會刪掉來源分支。開好之後標題列會出現「開啟 MR」。commit 成功但 MR 開不起來時，會另外提示，commit 本身不受影響。
- 之後可以繼續 commit 到同一條分支，不會再開新的 MR。
- **推回原分支**：把分支名稱改成目前跟著的那一條，就是直接推回去、不開 MR（需要那條分支的推送權限）。

### 常見錯誤

| 訊息                      | 原因與處理                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------- |
| 連不上 …                  | 位址打錯、網路不通，或這台 GitLab 擋了跨來源請求。檢查位址，自架的請管理員放行 CORS               |
| token 無效或已過期（401） | 到 GitLab 重新申請一個有 `api` 權限的 token                                                       |
| 權限不足（403）           | token 沒有 `api` 權限，或帳號沒有這條分支的推送權限（例如受保護的分支）。改推到新分支或請人加權限 |
| 找不到（404）             | 專案、分支或路徑打錯，或這個 token 看不到這個專案                                                 |
| GitLab 回 HTTP …          | 其他錯誤，後面會附上 GitLab 回的訊息                                                              |
| … 在這中間被推過了        | 載入之後有人推了新的 commit。重新載入再改一次                                                     |
| token 不見了              | 沒勾「記住」又關過分頁。重新按「從 GitLab 載入…」填一次                                           |

## 部署到 Vercel

產物是純靜態檔，部署在 Vercel 上：

1. 在 Vercel 匯入這個 repo。
2. 不用改任何設定：`vercel.json` 已經指定 `framework: vite`、`npm run build`、輸出 `dist`。
3. 不需要設定環境變數。
4. 不需要 rewrites：只有 `index.html` 一個入口，沒有前端路由。
5. `vercel.json` 對所有路徑加了 `X-Content-Type-Options: nosniff` 和 `Referrer-Policy: no-referrer`。

Vercel 預設就是 HTTPS，File System Access API 需要的 secure context 已經滿足。GitLab 整合沒有 OAuth，所以 Vercel 的網域不用在 GitLab 註冊；自架 GitLab 只要允許來自這個網域的跨來源請求。

要放其他地方也可以，任何 HTTPS 的靜態空間都行：`npm run build` 之後把 `dist/` 放上去，網站要從網域根目錄提供。

## 開發

Vite、React、TypeScript。UI 元件用 [shadcn/ui](https://ui.shadcn.com)（Radix + Tailwind CSS v4），表格是自己畫的（虛擬捲動用 `@tanstack/react-virtual`），狀態放在 Zustand，草稿用 `idb-keyval`，zip 用 `fflate`。

### 指令

| 指令                   | 作用                                     |
| ---------------------- | ---------------------------------------- |
| `npm run dev`          | 開 dev server：<http://127.0.0.1:5180>   |
| `npm run build`        | 型別檢查並產出 `dist/`                   |
| `npm run preview`      | 預覽 build 結果：<http://127.0.0.1:5181> |
| `npm test`             | 跑一次單元測試（Vitest）                 |
| `npm run test:watch`   | 測試的 watch 模式                        |
| `npm run lint`         | ESLint                                   |
| `npm run typecheck`    | 只做型別檢查（`tsc -b`）                 |
| `npm run format`       | 用 Prettier 格式化                       |
| `npm run format:check` | 檢查格式，不改檔案                       |

dev server 綁 `127.0.0.1`，因為 File System Access API 需要 secure context，`http://127.0.0.1` 算，`file://` 不算。port 固定，被占用時會直接失敗而不是換一個：偏好、草稿和記住的 token 都綁在 origin 上，換 port 就讀不到了。

`tests/fixtures/` 是逐位元比對用的語系檔樣本，`.prettierignore` 和 `.gitattributes` 都排除了它，不要格式化或改換行字元。

### 程式結構

| 路徑                     | 內容                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------- |
| `src/core/`              | 純函式：攤平 / 序列化、key 規則、版面判斷、變更追蹤、篩選、欄位配置。不碰 DOM，有測試 |
| `src/io/`                | 本機資料夾讀寫、下載與 zip、IndexedDB 草稿、版面偏好、記住的樣板                      |
| `src/gitlab/`            | GitLab REST API、token 存放（`auth.ts`）、路徑整理與錯誤訊息                          |
| `src/store/`             | Zustand store 與所有動作（載入、編輯、增刪 key / 語系、存檔、commit）                 |
| `src/components/`        | 頂端列、工具列、語系列、分區、顯示欄位選單等介面                                      |
| `src/components/grid/`   | 表格。熱路徑，用 CSS Modules 而不是 Tailwind                                          |
| `src/components/gitlab/` | GitLab 載入精靈與提交對話框                                                           |
| `src/components/ui/`     | shadcn 產生的元件，可以直接改                                                         |
| `src/debug.ts`           | 開發用的 console 工具，只有 dev server 會載入                                         |
| `tests/`                 | 單元測試（core 與 GitLab 輔助函式）和語系檔樣本                                       |

### 效能設計

- **單格更新只重畫那一列**：編輯中的資料是可變的，改完只更新那一列的版本號；載入、增刪 key、換篩選這類結構變動才整張表重算。
- **拉欄寬不經過 React**：欄寬與凍結位移是表格根節點上的 CSS 變數，拖曳時只改變數，放手才寫進 store。

### 除錯工具

- **`window.i18nDeskDebug`**：只有 `npm run dev` 時才有，正式 build 不會包進去。可以在 console 拿到 `state`、`serialize(code)`、`serializeComments()`、`changedFiles()`，以及直接驅動動作、回答對話框的 `actions` / `dialog`。`state.gitlab` 是 GitLab 連線狀態，不含 token。
- **`?nofsa`**：dev server 的網址加上 `?nofsa`（<http://127.0.0.1:5180/?nofsa>），假裝瀏覽器不支援 File System Access API，在 Chrome 上也能測 Firefox / Safari 的唯讀路線。正式 build 沒有這個開關。
